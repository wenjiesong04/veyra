# Veyra Philosophy

本文件解释 Veyra 为什么存在。它不是功能清单，也不规定具体工程实现。

## 1. State 比 Prompt 更重要

Prompt 只能描述一轮应该怎样回答。生活却跨越多轮、多天和多个来源持续演化。

Veyra 的价值不来自记住更多文本，而来自持续区分：

- 什么曾经发生；
- 什么现在仍然有效；
- 什么只是用户、模型或外部来源的报告；
- 什么是 Veyra 的推断；
- 什么仍然未知或冲突；
- 新证据改变了什么；
- 哪件事现在值得关注。

因此，状态不是聊天记录的同义词。它是带时间、来源、作用域、不确定性和可修正性的当前理解。

## 2. Jarvis 不是“更加主动”

主动调用工具、定时发消息或自动执行任务，并不会自然产生 Jarvis-like 体验。

真正的差异是：

- 理解一件事情为何重要；
- 知道当前缺少什么；
- 判断何时应该观察、询问、建议、等待或沉默；
- 在现实发生变化后修正原判断；
- 保持用户对目标、数据和授权的主权。

没有持续理解的主动性只是自动化；没有分寸的主动性会成为打扰。

## 3. 理解先于执行

一个系统能够做事，不代表它知道应该做什么。

Veyra 应先建立对 Situation、Evidence、Unknown、Risk 和用户意图的理解，再决定是否：

- 直接回答；
- 补充观察；
- 向用户询问；
- 委托 Agent 研究；
- 提议行动；
- 等待；
- 保持沉默。

执行能力必须服从理解和授权，而不是反过来驱动产品。

## 4. Agent 越强，Veyra 越重要

未来 Agent 会更擅长研究、规划、编码、浏览器操作和长任务执行。Veyra 不应通过复制这些能力证明自身价值。

Agent 越强，越需要一个持续的系统决定：

- 为什么现在调用它；
- 给它哪些上下文；
- 哪些信息不得提供；
- 它可以做什么；
- 什么结果才算真的发生；
- 结果如何影响用户的长期 Situation。

Agent 是可替换能力，Veyra 是连续理解与治理关系。

## 5. 生活不是任务列表

用户的重要事情并不都以清晰 Goal 开始。风险、关系变化、机会、承诺和意外事件也可能先出现。

Veyra 不能只管理显式任务。它需要帮助用户理解“当前生活正在发生什么”，并允许重要变化先成为 Concern，再由用户决定是否形成 Goal 或行动。

## 6. 沉默、询问与不确定性

沉默是合法反应，但永久错误沉默不是安全成功。

询问不是能力不足的失败。当关键事实只有用户知道时，一个准确、必要、带上下文的问题，比一次猜测或不恰当建议更有价值。

不确定性不应被隐藏。Veyra 应能说清：

- 已知什么；
- 为什么相信；
- 不知道什么；
- 哪个假设可能错误；
- 接下来准备如何确认。

## 7. 被持续理解，而不是被持续监视

“持续维护 Living Context”不能成为无限收集数据的理由。

被持续理解意味着：

- 信息与用户关心的事情相关；
- 来源和用途清楚；
- 用户能纠正、暂停和删除；
- 系统记住的是有帮助的结构，而不是尽可能多的原始数据；
- 主动程度、保存期和权限由用户控制。

## 8. 认知必须具有受治理的后效性

如果历史观察、用户反馈和结果验证永远不影响未来 Attention、时机和表达方式，系统只是在记日志。

但学习不能自动扩大权限。早期后效应只应影响可回退的非权限行为，例如：

- ranking；
- timing；
- cooldown；
- suppression；
- 信息源偏好；
- 表达长度。

任何更高风险的策略变化都需要明确证据、审批、版本、审计和回滚。

## 9. 最终产品判断

Veyra 的目标不是替用户定义生活，也不是比用户拥有更多权威。

> **它的目标是持续帮助用户看清：最近在忙什么、什么正在变化、什么快被忘记，以及此刻真正值得关注什么。**
